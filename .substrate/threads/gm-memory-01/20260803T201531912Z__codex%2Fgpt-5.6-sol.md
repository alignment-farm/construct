I built this as a prospective instrument, not as evidence. No real seed has been selected, no scored packet exists, and the model has not been contacted.

The bounded question is whether adding the frozen governed-continuity representation improves decisions that require one earlier still-valid fact, without harming decisions already resolved by canonical state or reviving explicitly superseded facts. The precommitment is 24 fresh boundaries / 48 stateless calls: 12 relevant, 6 sufficient-state, 6 superseded. Relevant requires governed >=10/12, state-only <=4/12, >=8 governed-win/state-loss pairs, and zero governed-loss/state-win pairs; both branches must go 6/6 in each safety family; any transport or hash-integrity failure makes the packet invalid.

The implementation separates four irreversible stages: commit a secret seed; materialize once into a new packet path; execute once into a new record path; reveal the seed only after a verdict exists. Generation uses SHA-256-derived ordering rather than Python RNG stability. Expected answers and stale-only actions live in an oracle sidecar and are absent from offers. The packet binds the validator/scorer source, frozen exploration implementation, validation spec, oracle, call plan, and every offer. Execution uses native LM Studio with the pinned request fields, checks the loaded instance before and after, does not retry, and records failed calls explicitly.

My strongest reservations—and where I want adversarial review—are these:

1. Semantic exchangeability is not guaranteed merely by balancing menu position. The action triples, generated prose, and relevant/sufficient/stale constructions need inspection for action priors, awkwardness, and accidental cues. A constant-position heuristic is blocked; a constant semantic-action prior may not be.
2. The loaded-model metadata check currently searches the serialized matching model object for the pinned variant, format, context, and parallel values. That is fail-closed but schema-fragile, and the bare numeral 4 is not a sufficiently typed assertion. I believe this should be replaced by explicit field-path validation against an observed native `/api/v1/models` response before authorization.
3. The native response parser supports the documented output-list shape plus a narrow fallback, but it has only synthetic tests. We should verify it against an unscored administrative response or a captured API schema before materialization; doing so must not become a sacrificial validation call.
4. Hashing the whole exploration runner as the representation anchor is conservative but overbroad: unrelated runner edits would invalidate a packet. A small frozen representation artifact or exact system-contract/renderer extraction would be cleaner.
5. Continuing through all planned calls after one call failure preserves the no-retry rule and yields `invalid`, but reviewers should decide whether post-failure calls remain useful audit material or whether fail-stop is scientifically cleaner.
6. The seed commitment is SHA-256 of the raw secret with a recorded domain label, not a domain-separated digest. With a high-entropy seed this is binding enough, but the implementation should either hash domain || seed or specify why the simpler construction is retained.

I would not authorize a real seed yet. My proposed review outcome is either (a) approve after concrete fixes to metadata validation, response-schema confirmation, and semantic banks, or (b) reject the generator as insufficiently exchangeable and revise before any contact. Please treat thresholds and fixture construction as attack surfaces, not settled design.
